Admin key checker

Who holds the admin key behind a contract?

Paste a contract address and see who holds the admin keys behind it (owner(), admin(), the proxy admin): a single account, a Safe, another contract. The page reads these standard places in your browser and says what it could not read, including when it cannot tell who can change the code. No wallet, no account, nothing to pay.

Or try a real one:

This link carries a contract address. Nothing has been read yet: press “Read this contract” to read it.

Ethereum mainnet only. The address you type is sent only to ethereum-rpc.publicnode.com, eth.drpc.org, 1rpc.io, the next one only if the previous one fails. Nothing is sent when this page opens or when you open a shared link.

Separate research, not repeated by this page. As of the research README of 14 October 2026 (repository head a0a9f9d; last research pass 30 September 2026): 108 entries (protocols and vault owner addresses) checked by hand, 30 of them recorded as single-key admin cases. Checked against that README on 30 October 2026. Cases were checked on different dates; a key checked earlier can read differently today.

      What this tool reads, and what it does not prove
      
  
      
    
      Method
      In your browser, at one block fixed when you press the button: owner(), admin(), the EIP-1967 admin, beacon and implementation slots, and the legacy ZeppelinOS admin and implementation slots. Every non-zero address found is a key: no code means a single account, getOwners() with getThreshold() means a Safe, another contract is followed through one owner() step. “Renounced” only when a getter returns the zero address and no proxy admin or beacon is stored. This is a simplified, free subset of the research method.
      
    
      Not read
      Role-based access control (OpenZeppelin AccessControl), proxy admins fixed in the code, Safe modules and guards, timelock delays, other chains, and who the people behind any key are. A node error, a timeout, or a node that has not reached the block is not treated as an answer: the next node is tried, and if all fail no result is shown. Only a revert by the contract itself counts as an answer.
      
    
      What a reading is
      A fact about how control is set up, read from public chain data. It is not an audit, not a score and not a judgment on any key.
      
    
      The numbers above
      As of the research README of 14 October 2026 (repository head a0a9f9d; last research pass 30 September 2026): 108 entries (protocols and vault owner addresses) checked by hand, 30 of them recorded as single-key admin cases. Checked against that README on 30 October 2026. Cases were checked on different dates; a key checked earlier can read differently today.
      
    
      Context: the Wasabi loss
      The research started from the Wasabi Protocol loss of 30 April 2026. The research README gives about $5.9M for that loss. That figure is the README’s, not a measurement by this page, and this page does not check that protocol.

      Privacy
      Static page, no account, no cookie, no analytics, no third-party script. The address you type goes only to the public nodes named above, and only after you press the button. The page loads no font and no image from another site. Your light or dark choice, if the site stores one, is kept by the site, not by this page.
