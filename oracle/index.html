Authority Risk Oracle

Who can really move a protocol's funds?

Most DeFi exploits are not code bugs. They are one admin key, one thin multisig, or one missing timelock. This oracle reads the real authority chain of each protocol from public chain state, scores it, and publishes the score on-chain, so a lending market, a DAO or a wallet can read it in one call and act on it without trusting anyone's website.

  • Read live from 9 oracles
  • Open source, MIT
  • No protocol pays for its score

What it scores

Five questions, answered from chain state

Sub-scoreThe question it answersWorst case
adminKeyScoreWho holds the upgrade or admin authority: a bare key, a Safe, a governance system?one EOA
multisigScoreIf a multisig: how many signers must agree, out of how many?1-of-N
timelockScoreIs there an enforced delay between a queued action and its effect?no delay
oracleAuthorityScoreWho can change the prices the target reports or reads? The scorers walk each price source one hop upstream.one price key
crossExposureScoreDoes the same committee also control another tracked protocol, on this chain or another?shared across chains

Integrate

Read it from a contract

A lending market can freeze collateral behind a weak authority and refuse a stale read outright. ExampleConsumer.sol ↗ does exactly that, with its tests.

interface IAuthorityRiskOracle {
    struct AuthorityScore {
        uint8 adminKeyScore; uint8 multisigScore; uint8 timelockScore;
        uint8 oracleAuthorityScore; uint8 crossExposureScore; uint8 compositeScore;
        uint64 lastUpdated; bytes32 methodologyHash;
    }
    function getScore(address target) external view returns (AuthorityScore memory);
    function isStale(address target) external view returns (bool);
}

// in your lending market
IAuthorityRiskOracle.AuthorityScore memory s = oracle.getScore(collateralProtocol);
require(!oracle.isStale(collateralProtocol), "authority score stale");   // an old score is no score
uint256 factorBps = s.compositeScore < 20 ? 0 : (uint256(s.compositeScore) * maxFactorBps) / 100;

Verified on-chain, and how to check it

  • The scores a consumer reads: contract storage, getScore(target).
  • Who may write a score: hasRole(UPDATER_ROLE, address).
  • A score is not too old: isStale(target).
  • Which code produced a batch: methodologyHash, recomputable from the scorer files.
  • Backtests on real incidents: the formula applied to the configurations behind Drift, Wasabi and Solend, in data/.
  • Corrections are published as data/correction_*.md, not edited away.

Limitations, stated plainly

  • Testnet publication. One updater key while the stack is validated; a mainnet deployment would move it to a multisig first.
  • Trust in the updater. The methodology hash, the public code and the push guard make a bad push detectable, not impossible.
  • Coverage is partial. 179 targets is a fraction of DeFi; coverage per ecosystem is measured by scripts/check_tvl_coverage.py.
  • Heuristics. Classifying an account and bounding a lever are documented, tested judgments, not proofs.
  • No external audit of the contract yet. It is small and was reviewed against the LlamaGuard pattern by this project itself.
