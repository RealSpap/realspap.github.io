The 27 hours before the PumpSwap upgrade

I replayed the buffer of the PumpSwap upgrade of 15 November 2026 transaction by transaction: its code was fully written at 13:49:21 UTC on 14 November and ran at 17:20:20 UTC on 15 November, 27 hours 31 minutes later.

27 h 31 minthe PumpSwap code sat finished in a public buffer before it ran

read at 19:04Z on 17 November 2026. This page needs no script and no tool to read.

At 17:20:20 UTC on 15 November 2026, the program PumpSwap (pAMMBay6oceH9fJKBRHGP5D4bD4sWpmSwMn52FMfXEA on Solana mainnet-beta) was upgraded in slot 469811067. An upgrade on Solana copies new code from a buffer account into the program, and anyone can read a buffer account before the upgrade runs. This page replays the life of that buffer, block by block, with the commands to do the same.

Block 469350301, 13:48:49 UTC on 14 November 2026. The buffer HBGEzR1n1ZKCN97KRSWQUSuBoM2CGXCZf2zpWCHbV6Fj on Solana mainnet-beta receives its earliest transaction.

Blocks 469350301 to 469350454, 13:48:49 UTC to 13:49:21 UTC on 14 November 2026. The buffer receives 1,258 transactions in all, and together they write 1,270,696 bytes of code. After block 469350454, the list of transactions of the buffer shows no other write.

Block 469354509, 14:03:45 UTC on 14 November 2026. The authority of the buffer passes from the account 92gWFZMpGhWzVq5tjBnJxF9VnFwE3ydB2idJp9z2D9Nr on Solana mainnet-beta to the account 7gZufwwAo17y5kg8FMyJy2phgpvv9RSdzWtdXiWHjFr8 on Solana mainnet-beta, the vault that later runs the upgrade. The transaction is 4pxAnPnuwD2rHZBz84WWCa7Kq8DrX3MskSmFyQTMNUnfSWMYP5sLD1fBxJJFzNYeVGGLDJ29o6spakWvtQbZe1SR.

From block 469350454 to block 469811067, no transaction touches the buffer except that change of authority. The newest three transactions of the buffer, listed by command 1 below, are the upgrade, the change of authority and the last write.

Block 469811067, 17:20:20 UTC on 15 November 2026. The vault 7gZufwwAo17y5kg8FMyJy2phgpvv9RSdzWtdXiWHjFr8 on Solana mainnet-beta runs the upgrade of the program from this buffer. The transaction is 2uB6vN55cWe95KmCpk5FH7jkaFoXjLt3MLDyETiLfuQVJzcUt1FeES8W1NEwJufvyQMeaWZfVdB7R1C7RELp8uCS.

The delays come from block times, which are estimates that validators attach to a block. From 13:49:21 UTC to 17:20:20 UTC the buffer was complete and waiting for 27 hours 30 minutes 59 seconds. From 14:03:45 UTC to 17:20:20 UTC, since the vault held its authority, 27 hours 16 minutes 35 seconds. The node api.mainnet-beta.solana.com and the node solana-mainnet.gateway.tatum.io return the same three block times.

The code that waited is the code that runs. I rebuilt the buffer from its write transactions: 1,270,696 bytes, SHA-256 d2ed30147f5eb202da7094567a7e5aec35d471487eeb8a081278c519d6b04966. I read the code held by the ProgramData account 6naEzKeUuFh1Jeeu51NXQgr5qkXgXtc9WKNct4xynVJc on Solana mainnet-beta, deployed at slot 469811067: its leading 1,270,696 bytes have the same SHA-256, and the rest of the account is zeros.

This page says nothing about why the program was upgraded, what changed in its code, who the signers are, who chose the timing, or whether 27 hours is long or short. The time lock of the multisig behind the vault is 0 seconds, as the note on the PumpSwap upgrade shows: the multisig itself imposed no delay, so the hours above are what happened, and no rule required them.

python3 -c '
import base64, hashlib, json, time, urllib.request
RPC = "https://api.mainnet-beta.solana.com"
BUF = "HBGEzR1n1ZKCN97KRSWQUSuBoM2CGXCZf2zpWCHbV6Fj"  # Solana mainnet-beta
PD = "6naEzKeUuFh1Jeeu51NXQgr5qkXgXtc9WKNct4xynVJc"  # Solana mainnet-beta
def rpc(m, p):
    for k in range(8):
        try:
            req = urllib.request.Request(RPC, json.dumps({"jsonrpc": "2.0", "id": 1, "method": m, "params": p}).encode(), {"content-type": "application/json"})
            r = json.loads(urllib.request.urlopen(req, timeout=60).read())
            if r.get("result") is not None: return r["result"]
        except Exception: pass
        time.sleep(2 + 2 * k)
    raise SystemExit("the node did not answer " + m)
sigs, before = [], None
while True:
    page = rpc("getSignaturesForAddress", [BUF, {"limit": 1000, **({"before": before} if before else {})}])
    sigs += page
    if len(page) != 1000: break
    before = page[-1]["signature"]
writes = {}
for s in sigs:
    tx = rpc("getTransaction", [s["signature"], {"encoding": "jsonParsed", "maxSupportedTransactionVersion": 0}])
    for i in tx["transaction"]["message"]["instructions"]:
        p = i.get("parsed")
        if isinstance(p, dict) and p.get("type") == "write" and p["info"]["account"] == BUF:
            writes[p["info"]["offset"]] = base64.b64decode(p["info"]["bytes"])
    time.sleep(0.12)
n = max(o + len(b) for o, b in writes.items())
code = bytearray(n)
for o, b in writes.items(): code[o:o + len(b)] = b
pd = base64.b64decode(rpc("getAccountInfo", [PD, {"encoding": "base64"}])["value"]["data"][0])
print(len(sigs), "transactions,", n, "bytes written")
print("buffer  ", hashlib.sha256(code).hexdigest())
print("program ", hashlib.sha256(pd[45:45 + n]).hexdigest())
'

Limit

A reading of public accounts and transactions on public nodes of Solana mainnet-beta between 13:26Z and 14:38Z on 16 November 2026 and again at 19:04Z on 17 November 2026 (the list of transactions of the buffer, the block times and the ProgramData account; the written bytes are those of the transactions read on 16 November, which a confirmed transaction does not change), each node answering with the genesis hash of that network. The buffer account no longer exists, so its content is rebuilt from the transactions that wrote it. The list of its transactions comes from the node api.mainnet-beta.solana.com, which keeps this history; another public node returns recent blocks only. The second node, solana-mainnet.gateway.tatum.io, answers five requests per minute on its free plan, hence the pause in the third command. The last command sends about 1262 requests and took about 65 minutes on that node on 16 November 2026. A later upgrade of PumpSwap would change the code held by ProgramData, and the last command would then print a different second hash.
