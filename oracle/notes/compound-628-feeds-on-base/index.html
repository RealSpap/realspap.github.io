Compound 628: two price feeds the Base message would set

I read the open Compound proposal 628, on Ethereum mainnet (chain ID 1), and the Base contracts it would call, on two public nodes per chain. Its single action is a message to Base that would set 2 price feeds and upgrade the 2 markets that use them; at the block read the vote is open and nothing has run.

The message goes to 0x18281dfc4d00905da1aaa6731414eaba843c468a on Base (chain ID 8453), a contract that answers crossDomainMessenger() with 0x4200000000000000000000000000000000000007, govTimelock() with 0x6d903f6003cca6255d85cca4d3b5e5146dc33925, which is the Timelock of the Governor on Ethereum mainnet (its timelock() answer on Ethereum mainnet), and localTimelock() with 0xcc3e7c85bb0ee4f09380e041fee95a0caedd4a02. The Configurator 0x45939657d1ca34a8fa39a924b71d28fe8431e581 on Base (chain ID 8453) answers governor() with 0xcc3e7c85bb0ee4f09380e041fee95a0caedd4a02, the local Timelock named above, and that Timelock reports a delay of 1 day. Limit

This page states what one open proposal sends and what the Base contracts hold at one block on Base (chain ID 8453). It says nothing about whether the proposal passes, when or whether the message would run on Base, why the feeds change, or how the new feeds behave. The message also upgrades each market with deployAndUpgradeTo: the code of those new implementations is outside what this page reads. Names of markets and assets come from nowhere on this page: addresses only. To see the effect after the message has run, read the same calls again at a later block.
