Read it yourself: who controls a contract, with a public RPC and curl

Two readers look at each tracked contract. The scorer feeds the score. The independent reader shares no code with it and answers one question: who can change this contract, and how many of them. All it does is plain JSON-RPC calls, listed here, so you can repeat it without trusting our code.

EVM chains: the calls, in this order

Set RPC to a public endpoint of the contract's chain, replace TARGET with the contract address, PROXYADMIN with the address found in step 2 and HOLDER with the address found in step 3 (answers are 32-byte words: the address is the last 20 bytes). Each call is a JSON-RPC request: curl -s -X POST $RPC -H 'content-type: application/json' -d '{"jsonrpc":"2.0","id":1,"method":"eth_call","params":[{"to":"TARGET","data":"0x8da5cb5b"},"latest"]}'. The contract pages show prefilled calls that re-read the published score under "Reproduce this read yourself"; the table below is the independent reader's path to the admin.

Step 5: what the holder is

Answer of eth_getCodeWhat it isWhat it means
0xA plain key (an EOA).One signature moves the contract. Stop.
0xef0100 + 20 bytes (23 bytes in all)A plain key with an EIP-7702 delegation.The key keeps all its rights, including signing a new delegation or removing this one. The 20 bytes after ef0100 are the address of the code the account runs when it is called: read eth_getCode on that address to see what it is. The independent reader counts it as one plain key. What the delegate code does is not analysed on this page.
Any longer codeA contract: a Safe, a timelock, a module.Climb. Safe: getThreshold() = 0xe75235b8, getOwners() = 0xa0e67e2b. Timelock: getMinDelay() = 0xf27a0c92 or delay() = 0x6a42b8f8. Then repeat step 5 on each signer. A Safe can also have modules, which execute without signatures (getModulesPaginated, selector 0xcc2f8452) and a guard in the slot 0x4a204f620c8c5ccdca3fd54d003badd85ba500436a431f0cbda4f558c93c34c8.

Solana programs: the calls

Set RPC to a Solana endpoint and use "encoding":"jsonParsed". All three calls are getAccountInfo.

StepCallHow to read the answer
1. The programgetAccountInfo(PROGRAM)Its owner must be BPFLoaderUpgradeab1e11111111111111111111111; data.parsed.info.programData is the ProgramData address. Another owner (an older loader, loader v4, a native program): not read by this page.
2. The ProgramDatagetAccountInfo(PROGRAMDATA)data.parsed.info.authority is the upgrade authority. null: the program cannot be upgraded.
3. The authoritygetAccountInfo(AUTHORITY)No account, or owner 11111111111111111111111111111111 (the System Program): a wallet address, go to 4. Owned by another program (Squads, a protocol): read that program.
4. On the curve?a local check, no callOn the ed25519 curve: a key pair can exist, count it as a plain key. Off the curve: a program-derived address, no key signs for it, a program does (a Squads vault, a protocol account): its holders are in that program.

Jupiter is the witness for the off-curve case; the Save authority has no account on chain yet (step 3 answers null), which is normal for a key that signs and holds nothing. On the curve does not say who holds the key: a custodian, a hardware key or an MPC setup is not visible from the chain, and several people can hold one key.

The curve check, in Python (standard library)
A = "123456789ABCDEFGHJKLMNPQRSTUVWXYZabcdefghijkmnopqrstuvwxyz"
def on_curve(b58):
    n = 0
    for c in b58: n = n * 58 + A.index(c)
    y = int.from_bytes(n.to_bytes(32, "big"), "little") & ((1 << 255) - 1)
    P = 2**255 - 19; D = -121665 * pow(121666, P - 2, P) % P
    if y >= P: return False
    u, v = (y * y - 1) % P, (D * y * y + 1) % P
    x2 = u * pow(v, P - 2, P) % P
    return x2 == 0 or pow(x2, (P - 1) // 2, P) == 1

What this reader does not probe

39 of the 203 reads are "unreadable": none of the steps above gave a holder. Known blind spots, found by checking twelve pages against the chain on 12 October 2026: contracts whose control sits behind governance(), gov(), feeToSetter() or upgradeAdmin() are not read by these steps, and an owner chain longer than two hops stops at the second. A 7702 delegate is read as an address, not as code: what the delegate does is not analysed. On Solana, a program-derived authority is named, not opened here. The scorer and the reader can both be wrong; a contract page says when they disagree.

If your own read differs from what a page shows, open an issue with your call and the answer: a disagreement is published, not smoothed.
